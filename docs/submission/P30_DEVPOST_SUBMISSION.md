## 3. The Problem: Why Green CI Lies

AI coding agents write and edit software at staggering velocity. To evaluate them, developers and benchmarks rely almost entirely on Continuous Integration: *if the test suite turns green, the change is accepted.*

**This assumption is fundamentally broken.** Green CI cannot prove causation:
1. **Pre-Existing Passing Tests**: Many tests pass before the agent touches the code because the test never exercised the edge case or assertion. The AI patch might do nothing—or introduce subtle regressions—while CI celebrates a false victory.
2. **Vacuous Assertions**: Large language models frequently solve test suites by modifying test files, weakening assertions, or mocking out components rather than implementing genuine behavioral repairs.
3. **Overfitted Patches**: A patch may pass a synthetic test without addressing the underlying invariant required by the system.

In software engineering, testing a candidate in isolation is insufficient. **If the patch matters, the base must break.**

---

## 4. The Solution: Basebreak's Three-World Causal Engine

Basebreak is an empirical verification runtime for AI-written code. Instead of trusting green tests, Basebreak evaluates an engineering change across three isolated execution worlds orchestrated inside **Nebius Token Factory Sandboxes**:

```
[World 1: BASE]           --> Run Sealed Witness --> FAIL (Exit 1)  [Defect is reproduced]
[World 2: CANDIDATE]      --> Run Sealed Witness --> PASS (Exit 0)  [Defect is resolved]
[World 3: COUNTERFACTUAL] --> Run Sealed Witness --> FAIL (Exit 1)  [Patch was necessary]
```

To achieve an overall verdict of **`VERIFIED`**, the run must strictly satisfy the **Causal Triplet**:
$$\text{BASE} = \text{FAIL} \quad \land \quad \text{CANDIDATE} = \text{PASS} \quad \land \quad \text{COUNTERFACTUAL} = \text{FAIL}$$

If the base does not fail, the witness did not exercise the bug. If the candidate does not pass, the patch did not fix it. And if reverting the patch in the counterfactual world does not fail, the patch was causally irrelevant to the outcome.

## 5. How We Built It: Architecture & Technical Implementation

Basebreak is engineered from the ground up to guarantee strict isolation, deterministic fact authority, and zero-friction inspection:

1. **AI Model Generation on Nebius Token Factory**:
   - Uses `nvidia/Nemotron-3_5-Lightning` hosted natively on Nebius Token Factory.
   - Candidate generation proposals are ingested and analyzed via **pure static AST inspection** (`ast.parse`) in Python 3.12+. Untrusted candidate code is never compiled, evaluated, imported, or executed on the host.
2. **Multi-World Nebius Sandboxes**:
   - Differential execution is executed across eleven discrete operations inside clean, isolated Nebius microVM sandboxes.
   - Each world materializes a fresh, immutable tree derived from the base commit (`80b43b84...`), isolating filesystem and network state.
3. **Cryptographic Fact Authority & Signing**:
   - The trusted verification bridge derives SHA-256 digests of all inputs, outputs, candidate git trees, and stderr/stdout logs.
   - Every completed run is authenticated with a **verifier-signed custom RSA-2048 cryptographic proof** generated by an isolated verifier signer.
4. **Cloudflare Workers & SQLite Durable Object Ledger**:
   - Hosted globally on Cloudflare Workers Free Tier (`https://basebreak.zyganali.workers.dev`).
   - Run receipts are committed to an SQLite Durable Object ledger.
   - Hackathon judges can inspect the full causal receipt, witness execution commands, and telemetry **completely signed-out with zero login friction**.
5. **Zero Personal Spend & Strict Financial Governance**:
   - Development and judging operate strictly under the **Zero-Cost Law**: target personal spend is **$0.00**.
   - Public endpoints are strictly read-only; no unmetered live execution endpoints exist that could drain promotional credits.

## 6. Meaningful External Grounding: Tavily Search Integration & Authority Firewall

Basebreak does not use search as decorative bonus theater. For tasks where code correctness materially depends on current external reality (e.g. `CVE-2024-21626` container escape security advisories or library API migrations), Basebreak integrates a bounded, deterministic Tavily Search adapter (`src/basebreak/adapters/tavily/`):

- **Tavily Grounds and Binds Advisory Information to an Already Frozen Contract**:
  Tavily queries official advisory registries and vulnerability databases (such as GitHub Advisory Database and security sources) to retrieve vulnerability mechanisms and affected/fixed version numbers (`<=1.1.11` vs `1.1.12`), binding these facts cryptographically to an already frozen engineering contract.
- **Sandboxes Verify WHETHER Code Satisfies It**:
  Nebius sandboxes execute the candidate against the sealed witness.
- **Deterministic Authority Firewall (`firewall.py`)**:
  External web search results **NEVER override code execution**. Web evidence has no authority to override deterministic execution, regardless of cryptographic digests. Even if Tavily returns an authoritative advisory stating that a vulnerability is patched, if the sandbox candidate fails, the firewall strictly outputs `PreliminaryVerdict.CONTRADICTED`.
- **Security & Integrity**:
  The Tavily client enforces bounded query validation, blocks credential and sealed witness token leakage, strips HTML/LLM answers, and strictly fails closed on adversarial prompt injection payloads (`INJECTION_BLOCKED`).
- **Scenario Separation & Live Evidence Boundary**:
  - The primary competition demonstration scenario (`ResetVault`, verified in live runs `run_3ba7d1fd` and `run_78fd00b7`) is an internal invariant test (`GroundingMateriality.NOT_APPLICABLE`) and did NOT use Tavily.
  - The Tavily integration is demonstrated under `CVE-2024-21626`.
  - The full offline pipeline, contract binding, adversarial defenses, and deterministic authority firewall are verified by automated tests.
  - Exactly ONE genuine live Tavily network provider execution was performed (`cbb8a550-d334-4727-a715-1086799a73f9`), recorded in `docs/evidence/p16_05_live_tavily_evidence_packet/tavily_cve_grounding_packet.json`. It recorded three external sources (`github.com/yandex-cloud/docs`, `github.com/advisories`, `security.snyk.io`), binding the external observation to the frozen contract. The deterministic authority firewall evaluated the evidence and strictly returned an honest fail-closed `INSUFFICIENT_GROUNDING / BLOCKED` verdict because temporal freshness and independent live-observation authority were insufficient (`unverified_freshness:fact-b882f0ea-03000bbf`), with candidate code execution strictly `NOT_RUN`. Web evidence possesses no authority to override deterministic execution, regardless of cryptographic digests.

## 8. Limitations & Honest Engineering Boundary

- **Empirical Causal Verification, Not Global Formal Proof**: Basebreak provides empirical causal evidence under the specified sealed witness. It proves the patch caused the observed state transition under that test; it does not claim formal mathematical correctness across all possible unstated inputs.
- **Synthetic Demo Scenario**: `ResetVault` is a synthetic security-sensitive scenario designed to clearly demonstrate differential 3-world causal mechanics and token replay protection; it is not a reproduced real-world CVE patch.
- **Witness Scope**: The live demonstration verifies one sealed behavioral witness (`wit-reset-vault-live-001`) under the canonical `ResetVault` scenario.
- **Signature Scheme**: The verifier signature uses custom 2048-bit raw modular exponentiation RSA over SHA-256 digests. It is independently verifiable across Python and Node.js, but is not standard PKCS#1 v1.5 or RSA-PSS.
- **Tavily Live Integration Boundary**: Exactly ONE genuine live Tavily request was executed (`cbb8a550-d334-4727-a715-1086799a73f9`, recording three sources bound to frozen contract), committed in `docs/evidence/p16_05_live_tavily_evidence_packet/`. The deterministic authority firewall correctly returned `INSUFFICIENT_GROUNDING / BLOCKED` due to insufficient temporal freshness/live-observation authority; candidate execution remained strictly `NOT_RUN`. Web evidence has no authority to override deterministic execution, regardless of cryptographic digests.
- **Human-Led Submission Boundary**: Submission text, storyboard, scripts, and guides are prepared in repository assets; physical video recording, voiceover audio generation, YouTube upload, and Devpost submission remain human-led operator tasks.
