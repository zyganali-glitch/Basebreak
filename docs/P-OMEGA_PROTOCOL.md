# P-Ω Integrity Protocol

P-Ω is a continuous integrity discipline, not a self-proving report.

## Focused checks on every task as relevant
- remote SHA and ancestry
- changed-file scope
- future-phase leakage
- deterministic assertions not weakened
- evidence provenance
- critical docs parity
- secret leakage
- donor reuse/provenance if touched

## Broad P-Ω audit triggers
- major phase closure
- first successful live Nebius spine
- security/authority boundary changes
- actual donor code introduction
- public demo milestone
- release candidate
- submission freeze

## Broad audit domains
1. repository/source identity
2. plan/status truth
3. architecture boundary
4. security/secret boundary
5. provider/model/runtime truth
6. evidence provenance
7. causal-verification semantics
8. donor provenance/licenses
9. tests/reproducibility
10. public/judge claims
11. competition eligibility
12. no future-phase leakage

A P-Ω document claiming PASS does not override contradictory source/runtime evidence.
